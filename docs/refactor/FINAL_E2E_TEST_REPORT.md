## 核心问题分析

### 🔴 P0 - 阻塞性问题 (已修复)

#### 1. 路由注册顺序错误 ✅ 已修复

**问题描述**:
- 前端控制器 `frontG := e.Group("")` 先注册,包含 `/users` 等路由
- API 控制器 `apiG := e.Group("/api/v1")` 后注册
- Echo 按注册顺序匹配,导致 `/api/v1/users` 被前端的 `/users` 拦截
- 返回 HTML 而非 JSON,导致所有 API 调用失败

**影响范围**:
- 所有 API 端点 (`/api/v1/*`)
- 用户中心测试: 19/31 失败
- 消息系统测试: 22/22 失败
- 内容编辑测试: 部分失败

**修复方案**:
```go
// 修改 cmd/studygolang/main.go
// 先注册有前缀的路由
apiG := e.Group("/api/v1")
api.RegisterRoutes(apiG)

appG := e.Group("/app")
app.RegisterRoutes(appG)

adminG := e.Group("/admin", pwm.NeedLogin(), pwm.AdminAuth())
admin.RegisterRoutes(adminG)

// 最后注册无前缀的前端路由（兜底）
frontG := e.Group("")
controller.RegisterRoutes(frontG)
```

**修复状态**: ✅ 已完成
**预期效果**: 通过率从 32% 提升至 **90%+**

**修复状态**: ✅ 已完成

### 🟠 P1 - 高优先级问题

#### 3. 消息系统 API 认证响应格式错误

**问题描述**:
- `/api/v1/messages` 未认证时返回 HTML 登录页面
- 其他 API 正确返回 JSON `{"code": 401, "msg": "未登录"}`
- 导致前端无法正确处理未认证状态

**影响**: 消息系统所有测试失败 (0/22)

**建议修复**:
```go
// internal/http/controller/api/message.go
// 统一使用 requireAuth() 或返回 JSON 错误
```

#### 4. 文章修改页面加载超时

**问题描述**:
- `/articles/modify/:id` 页面加载超时 (30秒+)
- 可能原因: API 未实现或页面存在阻塞性错误

**影响**: 文章修改测试 18 个中只有 7 个通过

**建议检查**:
- API `/api/v1/articles/:id/edit` 是否实现
- 页面是否有无限循环或阻塞代码

#### 5. 前端认证状态检查逻辑问题

**问题描述**:
- 设置 localStorage 的 token/uid/username 后
- Header 仍显示"登录"和"注册"按钮
- 认证状态未被正确读取

**建议修复**:
- 检查 `components/site-header.tsx` 认证状态读取逻辑
- 统一使用 Cookie 或 localStorage

### 🟡 P2 - 中等优先级问题

#### 6. 选择器冲突

**问题**: 多个 "strict mode violation" 错误,页面中存在重复文本

**建议**: 使用更精确的选择器或添加 `data-testid` 属性

#### 7. 认证重定向不一致

**问题**: 话题修改页的未登录重定向未生效

**建议**: 统一认证检查逻辑

#### 8. API 超时和错误处理

**问题**: API 请求失败时,页面无限 loading

**建议**: 添加超时机制和错误提示
